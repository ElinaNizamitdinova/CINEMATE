# CINEMATE

Веб-каталог фильмов и сериалов.

## Информация о проекте

- **Дисциплина:** Введение в интернет-технологии
- **Вариант:** № 21
- **Практические работы:** № 1, 2 и 3
- **Технологии:** HTML5, CSS3, JavaScript, Python, FastAPI, SQLite
- **Внешний источник данных:** TVmaze API
- **Библиотеки серверной части:** pwdlib (Argon2), PyJWT
- **Система контроля версий:** Git, GitHub

## Описание проекта

CINEMATE — веб-каталог фильмов и сериалов, предназначенный для просмотра информации о кинопроизведениях, поиска и фильтрации каталога, формирования персонального списка «Посмотреть позже» и выставления пользовательских оценок.

### Назначение файлов

- `index.html` — главная страница с подборкой популярных фильмов из собственной базы данных и подборкой сериалов из внешнего API.
- `auth.html` — страница регистрации и входа пользователей.
- `catalog.html` — каталог фильмов и сериалов с поиском, фильтрацией и сортировкой.
- `movie.html` — страница с подробной информацией о фильме или сериале, добавлением в список и выставлением оценки.
- `watchlist.html` — персональный список «Посмотреть позже».
- `contacts.html` — контактная информация и форма обратной связи.
- `css/style.css` — общие стили сайта.
- `js/backend.js` — общие функции взаимодействия с собственным сервером, обработка запросов и хранение JWT-токена.
- `js/auth.js` — регистрация, авторизация и выход из аккаунта.
- `js/home.js` — загрузка и отображение популярных произведений из базы данных.
- `js/api.js` — получение и отображение данных из TVmaze API.
- `js/catalog.js` — загрузка каталога, поиск, фильтрация, сортировка и добавление произведений в список.
- `js/contacts.js` — проверка данных формы обратной связи.
- `js/movie.js` — загрузка информации о произведении, добавление в список и обработка пользовательских оценок.
- `js/watchlist.js` — загрузка и отображение списка просмотра пользователя, удаление произведений.
- `images/movies/` — изображения фильмов и сериалов.


## Используемые технологии

### Клиентская часть

- **HTML5** — создание структуры страниц и семантической разметки.
- **CSS3** — оформление страниц, Flexbox, Grid и адаптивная вёрстка.
- **JavaScript** — реализация интерактивных функций сайта.
- **Fetch API** — асинхронное получение данных с сервера и внешнего API.
- **TVmaze API** — получение информации о сериалах.
- **localStorage** — хранение JWT-токена авторизации пользователя в браузере.

### Серверная часть

- **Python** — язык программирования серверной части.
- **FastAPI** — разработка REST API и обработка HTTP-запросов.
- **SQLite** — реляционная база данных для хранения информации о пользователях, фильмах, оценках, списках и подборках.
- **pwdlib (Argon2)** — хеширование и проверка паролей.
- **PyJWT** — создание и проверка JWT-токенов для аутентификации пользователей.
- **Pydantic** — проверка и валидация входящих данных.

### Инструменты разработки

- **Git и GitHub** — контроль версий и хранение исходного кода проекта.
- **Swagger UI** — просмотр документации API и тестирование серверных обработчиков.

## Хранение данных

Для хранения данных приложения используется реляционная база данных SQLite. База данных находится в файле `backend/cinemate.db`.

В базе данных созданы шесть связанных таблиц.

### Структура базы данных

**1. Таблица `users` — пользователи**

| Поле | Тип данных | Описание |
|---|---|---|
| `id` | INTEGER | Первичный ключ, идентификатор пользователя |
| `username` | TEXT | Имя пользователя, уникальное, обязательное |
| `email` | TEXT | Электронная почта, уникальная, обязательная |
| `password_hash` | TEXT | Хеш пароля, обязательное поле |
| `created_at` | TEXT | Дата и время создания записи |

**2. Таблица `catalog_items` — фильмы и сериалы**

| Поле | Тип данных | Описание |
|---|---|---|
| `id` | INTEGER | Первичный ключ |
| `title` | TEXT | Название произведения |
| `item_type` | TEXT | Тип контента: фильм или сериал |
| `release_year` | INTEGER | Год выпуска |
| `genres` | TEXT | Жанры |
| `description` | TEXT | Описание |
| `poster_url` | TEXT | Ссылка на постер |
| `created_at` | TEXT | Дата и время добавления |

Для поля `item_type` предусмотрено ограничение: допускаются только значения `movie` и `series`.

**3. Таблица `ratings` — пользовательские оценки**

| Поле | Тип данных | Описание |
|---|---|---|
| `id` | INTEGER | Первичный ключ |
| `user_id` | INTEGER | Внешний ключ на `users.id` |
| `item_id` | INTEGER | Внешний ключ на `catalog_items.id` |
| `score` | INTEGER | Оценка от 1 до 5 |
| `created_at` | TEXT | Дата и время создания оценки |

Для каждой пары «пользователь — произведение» допускается только одна оценка.

**4. Таблица `watchlist` — список «Посмотреть позже»**

| Поле | Тип данных | Описание |
|---|---|---|
| `id` | INTEGER | Первичный ключ |
| `user_id` | INTEGER | Внешний ключ на `users.id` |
| `item_id` | INTEGER | Внешний ключ на `catalog_items.id` |
| `added_at` | TEXT | Дата и время добавления |

Повторное добавление одного произведения в список одного пользователя запрещено.

**5. Таблица `collections` — тематические подборки**

| Поле | Тип данных | Описание |
|---|---|---|
| `id` | INTEGER | Первичный ключ |
| `user_id` | INTEGER | Внешний ключ на `users.id` |
| `name` | TEXT | Название подборки |
| `description` | TEXT | Описание подборки |
| `created_at` | TEXT | Дата и время создания |

Каждая подборка принадлежит определённому пользователю.

**6. Таблица `collection_items` — состав подборок**

| Поле | Тип данных | Описание |
|---|---|---|
| `collection_id` | INTEGER | Внешний ключ на `collections.id` |
| `item_id` | INTEGER | Внешний ключ на `catalog_items.id` |

Для таблицы используется составной первичный ключ `collection_id, item_id`, который предотвращает повторное добавление одного произведения в одну подборку.

### Связи между таблицами

- `users` — `ratings`: один пользователь может иметь несколько оценок.
- `catalog_items` — `ratings`: одно произведение может иметь оценки от разных пользователей.
- `users` — `watchlist`: у одного пользователя может быть несколько записей в списке «Посмотреть позже».
- `catalog_items` — `watchlist`: одно произведение может находиться в списках разных пользователей.
- `users` — `collections`: один пользователь может создавать несколько подборок.
- `collections` — `collection_items`: одна подборка может содержать несколько произведений.
- `catalog_items` — `collection_items`: одно произведение может входить в несколько подборок.

Таким образом, связь между подборками и произведениями реализована по принципу «многие ко многим» через промежуточную таблицу `collection_items`.

Для обеспечения целостности данных используются первичные и внешние ключи, ограничения уникальности и проверки допустимых значений. При удалении пользователя или произведения связанные записи автоматически удаляются благодаря ограничению `ON DELETE CASCADE`.

Пароли пользователей не хранятся в открытом виде. В базе данных сохраняются их хеши, созданные с использованием библиотеки Argon2.
## Внешний источник данных

Для получения информации о сериалах используется [TVmaze API](https://www.tvmaze.com/api).

Данные загружаются асинхронно и отображаются на главной странице проекта.

При возникновении ошибки загрузки пользователю выводится соответствующее сообщение.

## Запуск проекта

### 1. Запуск серверной части

Для запуска серверной части необходимо установить Python и зависимости проекта.

Откройте терминал в корневой папке проекта и выполните команды:

```bash
python -m venv .venv
```

Активация виртуального окружения в Windows:

```powershell
.venv\Scripts\Activate.ps1
```

Установка зависимостей:

```bash
pip install -r backend/requirements.txt
```

Запуск сервера:

```bash
cd backend
uvicorn main:app --reload
```

После запуска сервер будет доступен по адресу:

`http://127.0.0.1:8000`

Документация и тестирование API доступны по адресу:

`http://127.0.0.1:8000/docs`

### 2. Запуск клиентской части

Откройте файл `index.html` в браузере или запустите проект через локальный сервер, например в Visual Studio Code.

### 3. База данных

При первом запуске сервер автоматически инициализирует базу данных SQLite и создаёт необходимые таблицы. Для заполнения каталога начальными данными выполните из корневой папки проекта:

```bash
python -m backend.seed
```
